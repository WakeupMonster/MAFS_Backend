1 Verify Purchase /api/v1/subscription/verify POST ✅ Yes Verify in-app purchase from iOS/Android. Validates with Apple Server API or Google Play API. Handles both SUBSCRIPTION and CONSUMABLE product types. If source=FREE_TRIAL, checks milestone eligibility. Rate limited via apiLimiter. Joi validation on body. 
{
  "platform": "ios",
  "productId": "com.mafs.weekly",
  "transactionId": "2000000...",
  "purchaseToken": "optional_for_android"
}

Joi Validation:
- platform: required, "ios" | "android"
- productId: required
- transactionId: required for iOS
- purchaseToken: required for Android
 200 
SUBSCRIPTION:
{
  "success": true,
  "message": "Subscription verified successfully",
  "data": {
    "purchaseType": "SUBSCRIPTION",
    "subscription": {
      "id": "sub_id",
      "status": "ACTIVE",
      "planType": "weekly",
      "platform": "ios",
      "productId": "com.mafs.weekly",
      "startedAt": "ISO date",
      "expiresAt": "ISO date",
      "autoRenew": true
    },
    "status": { ...fullUsageStatus }
  }
}

CONSUMABLE:
{
  "success": true,
  "message": "5 SUPER_KEEN(s) added to your wallet!",
  "data": {
    "purchaseType": "CONSUMABLE",
    "consumableType": "SUPER_KEEN",
    "quantity": 5,
    "wallet": { ...walletData },
    "status": { ...fullUsageStatus }
  }
}
 400 
{
  "success": false,
  "error": "PLATFORM_MISMATCH",
  "message": "The Transaction ID provided is a Google Play ID (starts with GPA), but the platform is set to 'ios'."
}
{
  "success": false,
  "error": "Validation failed",
  "details": ["Platform is required", "Product ID is required"]
}
 1) Joi validation fails → 400: "Validation failed" + details[]
2) iOS transactionId starts with "GPA." → 400: PLATFORM_MISMATCH
3) Apple/Google API verification failure → next(err)
4) FREE_TRIAL source with expired/ineligible milestone → Error thrown
5) Xcode StoreKit bypass in dev mode
2 Restore Purchases /api/v1/subscription/restore POST ✅ Yes Restore previous purchases on new device. Loops through each purchase item, verifies with store API, and re-processes via handlePurchase. Returns full usage status after restore. 
{
  "platform": "ios",
  "purchases": [
    {
      "productId": "com.mafs.weekly",
      "transactionId": "2000000...",
      "purchaseToken": "optional"
    }
  ]
}

Joi Validation:
- platform: required, "ios" | "android"
- purchases: required array, min 1 item
  - productId: required
  - transactionId: optional
  - purchaseToken: optional
 200 
{
  "success": true,
  "message": "Purchases restored successfully",
  "data": {
    "restoredCount": 1,
    "items": [
      {
        "productId": "com.mafs.weekly",
        "status": "ACTIVE",
        "expiresAt": "ISO date"
      }
    ],
    "status": { ...fullUsageStatus }
  }
}
 400 
{
  "success": false,
  "error": "Validation failed",
  "details": ["purchases is required"]
}
 1) Joi validation fails → 400
2) Individual item restore failure → logged warn, skipped
3) next(err) on unhandled errors
