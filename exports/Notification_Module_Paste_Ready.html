# Sub-Module API Endpoint Method Auth Description Request Body Success Code Success Response Error Codes Error Response Error Scenarios ✏️ Improvements
1 Register Device Token /api/v1/notifications/register-token POST ✅ Yes Register FCM device token for push notifications. Removes existing entry for same deviceId first (prevents duplicates), then pushes new token with platform info to user's fcmTokens array. 
{
  "token": "fcm_device_token_string",
  "deviceId": "unique_device_id",
  "platform": "android"
}
 200 
{
  "success": true,
  "message": "Device token registered successfully"
}
 400, 500 
{
  "success": false,
  "message": "Token and deviceId are required"
}
{
  "success": false,
  "message": "Failed to register device token",
  "error": "error.message"
}
 1) token missing → 400: "Token and deviceId are required"
2) deviceId missing → 400: "Token and deviceId are required"
3) platform defaults to "android" if not provided
4) Internal error → 500: "Failed to register device token" + error.message
2 Unregister Device Token /api/v1/notifications/unregister-token DELETE ✅ Yes Remove FCM token for a specific device. Uses $pull to remove the matching deviceId entry from the user's fcmTokens array in User collection. 
{
  "deviceId": "unique_device_id"
}
 200 
{
  "success": true,
  "message": "Device token unregistered successfully"
}
 400, 500 
{
  "success": false,
  "message": "deviceId is required"
}
{
  "success": false,
  "message": "Failed to unregister device token",
  "error": "error.message"
}
 1) deviceId missing → 400: "deviceId is required"
2) Internal error → 500: "Failed to unregister device token" + error.message
3 Get Notification Settings /api/v1/notifications GET ✅ Yes Get current notification preferences for user. Fetches notificationSettings field from User model using .select("notificationSettings").lean(). 
None
 200 
{
  "success": true,
  "data": {
    "push": true,
    "email": true,
    "matches": true,
    "messages": true,
    "likes": true
  }
}
 404, 500 
{
  "success": false,
  "message": "User not found"
}
{
  "success": false,
  "message": "err.message"
}
 1) User not found → 404: "User not found"
2) Internal error → 500: err.message
4 Update Notification Settings /api/v1/notifications PATCH ✅ Yes Update notification preferences. Accepts both flat body and nested { notificationSettings: {} }. Converts string/number booleans via toBool(). Syncs changes to both User and Profile collections. Supported fields: push, email, matches, messages, likes. 
{
  "push": true,
  "email": false,
  "matches": true,
  "messages": true,
  "likes": false
}
OR
{
  "notificationSettings": {
    "push": true,
    "email": false
  }
}
 200 
{
  "success": true,
  "message": "Notification settings updated (Synced)",
  "data": {
    "push": true,
    "email": false,
    "matches": true,
    "messages": true,
    "likes": false
  }
}
 404, 500 
{
  "success": false,
  "message": "User not found"
}
{
  "success": false,
  "message": "err.message"
}
 1) User not found → 404: "User not found"
2) Internal error → 500: err.message
3) toBool() accepts: true/"true"/1/"1" → true and false/"false"/0/"0" → false
4) Syncs to Profile.notifications via $set
